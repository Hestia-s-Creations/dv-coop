# M3: shared rocks ("cells")

Goal: two or three players flying near each other see **the same asteroids, in the same places, moving the same way**,
and their ships collide with them consistently. Spec background: [SPEC.md](SPEC.md) sections *Decisions*,
*Game-side seams* and *Replication model*. Mining and damage between players is M4; M3 only has to keep it from
desyncing (members never fracture a rock locally).

## Gate

On `tools/dev3.sh` (R: ENet relay at the title screen; A at the dive target, B 5,000 px off, C 60,000 px off and warping in after 25 s):

1. A and B form a cell within 2 s of the later dive cutscene ending (nobody joins a cell mid-cutscene: the stock spawner clears the dive corridor, a shared field doesn't); the lower of their ids is authority (ENet client ids are random). A player who joins later never takes authority (incumbent rule, SPEC Decisions). C is alone.
2. Screen captures of A and B framed on the same spot show the same rocks (same shapes, same places, within ~20 px).
3. For 60 s, the rock nearest B agrees between A's and B's logs within 50 px (log both every 5 s by net id).
4. C warps (`--coop-warp-to-peer`) to 20,000 px: C joins the cell, its own rocks go, A's appear, no crash,
   no ship jump > 400 px.
5. The authority quits: the next-lowest id becomes authority of the remaining cell within 1 s and the rocks keep moving for both (no freeze, no mass vanish).
6. Zero `SCRIPT ERROR` lines in any `engine_log.txt`; authority upload logged and under 250 kB/s.
7. Resolutions: friend markers correct and readable, and every rock on screen synced at max zoom-out, at 1280x720, 1920x1080, 3440x1440, 1920x1200, 2560x1440 and 1280x1024.

## Interface between Cell and RockSync

Both are children of CoopNet (`get_parent()` / `net`). Each reads the other through these calls only:

```
# Cell.gd provides
func inCell() -> bool                # this machine is in a cell with at least one other player
func isAuthority() -> bool           # true when alone too (you simulate your own bubble)
func authority() -> int              # peer id of the cell authority (myId when alone)
func members() -> Array              # peer ids in the cell, including me; [myId] when alone
func gen() -> int                    # origin generation; RockSync tags every r.* packet with it and drops stale ones
signal cell_joined(authority_id)     # emitted AFTER origin adoption and spawner suspend (member) or on promotion
signal cell_left()                   # back to a solo bubble; spawner resumed
signal authority_changed(new_id)     # handoff inside a live cell

# RockSync.gd provides
func trackedCount() -> int
func releaseAll()                    # member leaving a cell: free tracked rocks (the spawner refills)
func promoteToAuthority()            # handoff: tracked rocks become locally simulated and start streaming
```

RockSync connects to Cell's three signals itself and calls its own `releaseAll` / `promoteToAuthority`; Cell never
frees rocks. A leaving player sends `bye` on quit; Cell also treats an authority silent for 0.9 s on its 5 Hz
`c.hb` as gone.

## Packets (CoopNet `net.on("<type>", self, "<method>")`, sent with `net.send` / `net.sendTo`)

All positions inside a cell are **origin-relative** (`global_position` after adopting the authority's
`CurrentGame.globalOffset`). Beacons stay global.

| Type | Who → who | Reliable | Body |
| --- | --- | --- | --- |
| `c.state` | authority → members | yes, on change and every 2 s | `cid`, `auth`, `members`, `off` (authority's globalOffset), `gen` (origin generation, +1 per slipstream) |
| `c.join` / `c.leave` | member → authority | yes | `gen` seen |
| `c.hb` | authority → members | no, 5 Hz | heartbeat |
| `r.s` | authority → member | yes | list of rock recipes (spawn); batched, max ~200 per packet |
| `r.d` | authority → member | yes | list of net ids (despawn / fractured) |
| `r.u` | authority → member | no | list of `[id, p, r, v, w]`; per receiver 10 Hz within 6,000 px of its ship, 2 Hz to 30,000 px, none beyond |
| `r.snap` | authority → new member | yes | `r.s` for every body within 30,000 px of the member, sent on `c.join` |

Net id = `"<owner peer id>:<counter>"` string, minted by whoever spawns. Every RigidBody2D entering the
`AsteroidField` gets one (node meta `dvnet`). RockSync watches `child_entered_tree` / `child_exiting_tree`, so it
needs no hook in the spawner. Only rocks are replicated: scenes `res://asteroids/class-*.tscn` (script
`asteroid.gd`) and `res://asteroids/mineral-*.tscn` (script `mineral.gd`). Oddities, ships and story bodies keep
their ids but aren't streamed in M3.

### Rock recipe

What `spawnAsteroidByClass` rolls, and what each rock's `_ready()` rolls, is enough to rebuild an identical rock. An
`r.s` / `r.snap` entry is an array:

`[id, kind, scale, p, r, v, w, class, k, estimatedRadius, splitsTo]`

| Field | Source on the authority | Rebuild on a member |
| --- | --- | --- |
| `kind` | scene file minus `res://asteroids/` and `.tscn` (`class-23`, `mineral-fe-4`); the spawner picks it by `randi()` from `objectClass[class]` (by vein for class 5) | `load()` that scene, `instance()` |
| `scale` | `additionalScale`, `rand_range(0.75, 1.25)` (asteroids only; minerals send 1) | set `additionalScale` before `add_child`; `asteroid._ready()` → `setScale()` sets sprite/collider scale and `mass = baseMass * s` |
| `p`, `r` | `global_position`, `global_rotation` (origin-relative) | `position`, `rotation` before `add_child` |
| `v`, `w` | `linear_velocity`, `angular_velocity` | set after `add_child` |
| `class` | `asteroidClass` | set before `add_child` |
| `k` | asteroid: `rnd` (onready `randf()`, feeds `getComposition()`); mineral: `mineralContent` (rolled in `_ready()` from `purity`) | after `add_child`. Asteroid: `rnd = k`. Mineral: rescale sprite and collider by `lerp(scaleMax, scaleMin, k) / lerp(scaleMax, scaleMin, rolled)`, then recompute `fillerContent`, `composition` and `mass` the way `mineral._ready()` does |
| `estimatedRadius` | `estimatedRadiusByClass[class] * s` unless the scene sets one | set before `add_child` |
| `splitsTo` | `clamp(5 - class, 1, 4)` for spawns, the scene default for shards | set before `add_child` (used only after a promotion) |

Mass, shape and texture follow from scene + scale (+ `k` for minerals). Members add the rock straight to the field.
They skip `spawnByBlueprint`'s intersection test and the density map, so nothing is rolled locally.

### RockSync behaviour

- **Authority**: per member, keeps the set of rock ids it has told that member about. Each tick it sends new rocks
  within 30,000 px of the member's ship (puppet position, beacon if no puppet yet) as `r.s`. Every 0.5 s it re-checks
  interest: rocks past 34,000 px, freed, or starting to fracture go out as `r.d`. Their shards arrive later as
  ordinary spawns. `r.u` is `{g, i: PoolStringArray ids, f: PoolRealArray [px, py, rot, vx, vy, w] per id}`: 10 Hz
  for known rocks within 6,000 px, 2 Hz beyond. A sleeping rock is sent once, then skipped until it wakes. A new
  entry in `Cell.members()` gets an `r.snap` (batches flagged `first` / `last`).
- **Member**: `r.s` / `r.snap` are upserts. The `last` snap batch frees tracked rocks the snap didn't name, so a
  handoff or a cell switch converges. Reliable packets are held, in order, until `Cell.authority()` is the sender and
  `gen()` has caught up. `r.u` from another generation is dropped. Each physics tick the correction aims at
  `p + v * age` (age ≤ 1 s, then the rock coasts): velocity `= v + err * 3`, snapping past 400 px or 0.8 rad.
  `ext/asteroid.gd` makes damage on a tracked rock (meta `dvnet_tracked`) cosmetic only. `ext/AsteroidSpawner.gd`
  never despawns a tracked rock, and blocks `slipstream()` on members.
- **Roles** are polled from Cell each tick. member → solo releases tracked rocks. Becoming a member frees our own
  rocks through `field.kill(rock, true)`, which keeps the density map balanced. `authority_changed(myId)` while a
  member promotes at once (before Cell's `cell_left`): tracked rocks lose `dvnet_tracked` and are counted into the
  density map.
- **Log**: `COOP: RS role=... rocks= tracked= sent s/d/u up=kB/s` every 5 s, with the 3 rocks nearest each receiver
  (authority) or nearest me (member), by net id, in global coordinates, for gate check 3.

## Known issues carried to M4

- Moving rocks trail on members by about one physics tick plus latency: a rock at ~95 px/s sits a steady ~6 px behind
  on one PC (slow rocks 0.2 px). Members extrapolate from packet arrival, not from the authority's sample time. Fix:
  `r.u` carries the authority's sample time and members extrapolate from a clock offset estimated from pings. Over a
  real network add latency x speed (100 ms at 100 px/s = 10 px more). Matters for M4 claw grabs; held rocks move to
  the holder (touch-to-own), which sidesteps it for the rock in hand.
- A cell member joining after an authority dies waits up to ~3.5 s for the dead cell's advert to go stale (harmless).
- Crash handoff takes 1.5 s (silence timeout); graceful quits hand off at once. Definition of done says under 1 s.

## Rules

- All network state is applied on the physics tick (CoopNet already calls modules from `_physics_process`).
- Members never spawn, fracture or despawn a tracked rock on their own. Authority messages only.
- Alone, nothing changes: the stock game runs untouched (Definition of done #9).
- Every new `ext/` script starts `extends "res://<original>"` and calls the parent for everything it doesn't change.
- `python tools/verify.py` must pass; run `python tools/verify.py --update` after changing files and commit the manifest.
