# M5: joining flows

Goal: a player never types a command line or a lobby id. They host, invite and join from the title screen or the
pause menu, accept a Steam invite with the game closed or running, and get to a friend from Enceladus (dive to their
marker) or from the ring (plot a course to them). Covers SPEC *Definition of done* items 2, 3 and 4, plus the
engineering item "reconnect after a drop returns a player to the same lobby and their own ship".

Owner: tim-06, branch `m5` (off `m4`), PR `m5` -> `m4`. Line numbers are the decompiled 1.90.12 under `reference/`; the key ones were
re-checked by hand. All mod UI follows the resolution rule from M3 gate 7: Containers and anchors only, the game's own fonts,
no fixed pixel positions.

### Reconnect and "join at any time"

- Saves happen only on New Game, on pressing Dive (before the charge), on arrival back at Enceladus, and on the
  station's Save buttons (CurrentGame.gd :327-356). **Nothing saves during a dive**: quitting mid-dive (Menu,
  Exit, window close) puts the player back at Enceladus, pre-dive, with that dive's loot lost.
- A drop mid-dive therefore doesn't need a "rejoin the same dive": the dropped player's game keeps running and
  re-syncs from beacons when the transport comes back. If the game itself was closed, "rejoin" = Continue, then
  dive to the friend (the dive picker flow), which is the stock cost of a new dive.
- CoopNet keeps the lobby id; on a transport drop it retries `joinLobby` with backoff (1, 2, 4, 8 s, then every 15 s)
  and shows "reconnecting" in the friend panel.

## Proposed UI

All of it in Containers inside the stock containers above (see Design, UI for the theme and font); sizes in canvas
units so it follows the game's UI scale.

**Title screen, "Co-op" button** (in `Opts`, above Exit) opens a panel in `Popups`:

```
+-- Co-op --------------------------------------+
| [ Host a game ]   friends-only, up to 5       |
| [ Invite friends ]  (Steam overlay)           |
| Lobby: 3 players   [ Leave ]                  |
| --------------------------------------------- |
| Friends playing ΔV co-op:                     |
|   Alice   in lobby 1234...  [ Join ]          |
|   Bob     at Enceladus                        |
| Save slot for joining: [ A v ]                |
+-----------------------------------------------+
```

Joining from here loads the chosen slot with the stock Continue; the player arrives at Enceladus in the lobby.

**Pause menu, "Co-op" button** (after Resume): the same panel without "Save slot", plus a line per friend with
zone and range ("Alice, rings, 34 km").

**Astrogation panel (flight)**: friend rows appended to the destination list, `Alice (friend), 312 km`, plotted with
the stock Plot Course button; a friend marker (chevron + name) on the big ring map.

**Dive picker (Enceladus)**: friend rows `Alice (friend)` in the destination list; the stock price, depth and dv
panels apply; Dive lands the player a few km from the friend.

**Friend overlay (flight HUD, exists)**: adds "lobby: N, reconnecting..." to the off-ring list when the transport drops.

## Design

### Session API (CoopNet)

Today the transport starts only from launch options. M5 adds a session that the UI drives, and keeps the launch
options as dev shortcuts that call the same functions.

| call / state | Steam | ENet dev transport |
| --- | --- | --- |
| `host()` | `createLobby(friends only, 5)`, rich presence `connect` = `+connect_lobby <id>` | connect to the dev relay (the relay is the "lobby") |
| `join(lobby)` | `joinLobby(id)` | connect to `host:port` |
| `leave()` | `bye`, `leaveLobby`, close P2P sessions, clear rich presence | `bye`, close the client |
| `requestJoin(lobby, from)` | every outside join request ends here: `join_requested`, `+connect_lobby`, the panel's Join | same, from `--coop-dev-invite` |
| `sessionState()` | `idle`, `hosting`, `joining`, `in lobby`, `reconnecting` | same |
| signal `session_changed` | the panel and the friend overlay redraw on it | same |

`requestJoin` decides by where the player is:
- **Title screen:** open the co-op panel in join mode. Join stays disabled until the chosen slot holds a save, so a
  join never starts on an empty slot (a player with no save is told to start a game first). Join = join the lobby,
  then the stock Continue on that slot, which lands at Enceladus.
- **Enceladus or in a dive:** ask first ("Join Alice's game? You keep your ship and your dive; you leave your
  current lobby."). Yes switches lobby; the ship, the dive and the save are untouched (a lobby only carries beacons;
  the cell re-forms from distance). No keeps the current lobby. The question opens with the pause menu (in a cell the
  menu doesn't pause, alone it pauses as stock).
- **Loading or in the dive cutscene:** queued and asked once the scene settles.

Reconnect: CoopNet remembers the lobby it is in. When the transport drops without a `leave()` (ENet
`server_disconnected` / `connection_failed`; Steam: every peer silent past 2 x BEACON_TIMEOUT while the lobby still
lists them, or the lobby lost), it retries `join` at 1, 2, 4, 8 s, then every 15 s, until it is back or the player
leaves. The player's own ship never stops: it is local. The others drop the puppet (peer gone) and re-spawn it from
the next beacon. On ENet the reconnected client gets a new peer id (a dev-transport artifact: Steam ids are
stable), so the others see a new peer with the same name.

### UI

One script, `ui/CoopPanel.gd`, built in code from Containers (no fixed pixel positions) and themed with the game's
own `menu/MenuTheme.tres`, so it looks like the game's menus and follows its UI scale. Its font is a copy of the
menu font (Audiowide, Latin only) with the HUD's Noto faces as fallbacks (Mono, CJK, JP, Thai, as in the friend
overlay), so Steam names in any script render. It lives in the title screen's
`NoMargins/Popups` CenterContainer, and in the pause menu's `PauseContainer/NoMargins/CenterContainer`, both
already centred by the game. The "Co-op" buttons are plain Buttons added to the stock VBoxContainers
(`ext/TitleMenu.gd`, `ext/PauseLayer.gd`).

Friend list: Steam friends whose game is ΔV with a lobby (`getFriendGamePlayed`) plus the lobby's members with their
beacon zone and range. On the ENet dev transport the list is the dev relay.

### Travel

- **Dive to a friend** (`ext/AstrogationDestinations.gd`, `ext/DiveTarget.gd`): friend rows `FRIEND|<peer>` with
  `time = 1` and the friend's beacon position, so the stock picker prices the dive there. After the stock
  `_on_Dive_pressed` (save, charge, random spread), `CurrentGame.diveTarget` is replaced by the friend's position,
  led by their velocity over the 15 s dive cutscene, minus the cutscene's own drift, plus 3 km off to the side.
- **Plot a course to a friend** (`ext/AstrogatorPanel.gd`): friend rows appended after the stock rows, `time = null`
  (no uncertainty), the stock 150 km minimum. Plot Course on a friend row emits `CurrentGame.plotCourseTo` directly
  (the stock `fastTravelTo` only knows save destinations). The ship's fast travel keeps a reference to the target
  dictionary and reads `vector` at the teleport, 5 s after the burn; a Travel tick keeps that `vector` on the
  friend's beacon until then. Nothing is written to `state.astrogation`.
- **Friend marker on the big ring map** (OMS): a Node2D per friend on the stock map, same pattern as `Labels.gd`.
  Stretch goal of M5; the friend overlay already shows name and range at any distance.

## Dev automation

All flows run on the ENet dev transport with a new launcher `tools/dev5.sh`: the relay R, then up to three players
started at the title screen (no autodive) with `--coop-dev-enet=127.0.0.1:7777`, which points Host and Join at the
relay instead of Steam. Flags drive the real buttons (they emit the Buttons' `pressed`, so the UI path is tested):

| flag | does |
| --- | --- |
| `--coop-dev-ui=<s>:<action>[,<s>:<action>...]` | at s seconds after the scene settles: `coop` (open the panel), `host`, `join`, `slot=<file>`, `invite`, `leave`, `continue`, `close`, `capture` (logs the panel's rect and the viewport size, for the resolution matrix) |
| `+connect_lobby <lobby>` | as Steam passes it; on ENet the lobby is `host:port` |
| `--coop-dev-invite=<s>,<lobby>` | a `join_requested` arriving s seconds into the current scene; `--coop-dev-answer=yes|no` answers the question |
| `--coop-dev-dive-friend=<s>` | at Enceladus: open the dive picker, select the first friend row, press Dive |
| `--coop-dev-plot-friend=<s>` | in a dive: select the first friend row in the astrogator, press Plot Course |
| `--coop-dev-drop=<s>,<dur>` | in a dive: cut the transport for dur seconds (no `bye`), then let the reconnect loop bring it back |
| `--coop-dev-ui-scene=<scene>` | run the `--coop-dev-ui` steps only in that scene (title, station, dive) |
| `--coop-dev-solo-pause=<s>,<s2>` | in a dive: pause alone as the stock pause does, close the menu at s2 (gate 8) |
| `--coop-dev-name=<name>` | my ENet name (dev5 names A, B, C); `--coop-dev-dive-friend=<s>,<name>` dives to that friend |

`tools/gate_m5.py` reads the logs, like `gate_m4.py`. Resolution captures use PowerShell `CopyFromScreen`
(docs/HANDOFF.md) with dev5's `RES_*` / `UI_*` options.

## Gate

Dev automation (ENet, one PC, at most 4 windows):

1. **Title flows.** B starts at the title, opens Co-op, picks its slot, Joins: it lands at Enceladus in the lobby,
   A's beacon arrives. The save picker lists only slots that hold a save; with none, Join is disabled. Host and
   Leave from the panel reach "in lobby" / "idle".
2. **Panel layout.** Title and pause panels at six window sizes covering both UI-scale extremes. After every rebuild
   the panel logs a layout report (dev runs only): inside the viewport, clear of the stock menu column, no control
   below its minimum size or outside the panel, no wrapped line cut. Every report must pass; the PrintWindow
   captures are kept as evidence.
3. **Invite while running.** A join request at the title opens the panel in join mode (answered with the save
   picker); at Enceladus and in a dive it asks first; "no" keeps the old lobby and the dive; "yes" switches lobby and
   keeps the ship and the dive. A `+connect_lobby` launch goes through the same path.
4. **Dive to a friend.** From Enceladus B arrives within 5 km of the friend's position at the moment of arrival and a
   cell forms; B pays the stock price for that spot; B's save changes only by the stock pre-dive save.
5. **Plot a course to a friend.** C, more than 150 km from A, arrives within 5 km of A; C's and A's saves are
   untouched (savecheck), so nothing reached `state.astrogation`.
6. **Reconnect.** B's transport is cut for 20 s mid-cell: B shows "reconnecting", comes back to the same lobby
   without a restart, still flying its own ship, and forms the cell again. (A closed game comes back through
   Continue + dive to friend, which is gates 1 and 4.)
7. Zero SCRIPT ERROR on every instance; `savecheck` passes for every flow except the stock pre-dive save; the M4
   gates still pass (the lead's `tools/m4_final.py` on `m4` after the merge).
8. **Paused alone, then a friend arrives.** C pauses alone (the stock pause, as on focus loss); when B arrives the
   menu turns into the cell-style menu (game running, menu up), the cell forms, and the menu still closes.

`python tools/gate_m5.py <logs>` scores gates 1-8 from the dev5 logs (`tools/dev5.sh`, flags in `net/Travel.gd`).

**Human gate (Tim; Steam P2P can't be proven on one machine):** a second machine with a second Steam account.
(a) Host and invite through the Steam overlay; accept with the game closed (`+connect_lobby`) and running
(`join_requested`), (b) "Join game" from the Steam friends list (rich presence), (c) dive to the friend and plot a
course to them over real P2P, (d) pull the network cable for 20 s and watch the reconnect, (e) a look at the panel
on both machines' screens. The Steam-only code is kept thin: `createLobby` / `joinLobby` / `leaveLobby`,
`getFriendGamePlayed`, `setRichPresence`, `activateGameOverlayInviteDialog` and the two join signals.
