# M5: joining flows (draft)

Goal: a player never types a command line or a lobby id. They host, invite and join from the title screen or the
pause menu, accept a Steam invite with the game closed or running, and get to a friend from Enceladus (dive to their
marker) or from the ring (plot a course to them). Covers SPEC *Definition of done* items 2, 3 and 4, plus the
engineering item "reconnect after a drop returns a player to the same lobby and their own ship".

Status: design draft, no code. Line numbers are the decompiled 1.90.12 under `reference/`; the key ones were
re-checked by hand. All mod UI follows the resolution rule from M3 gate 7: Containers and anchors only, the HUD font,
no fixed pixel positions.

## Found while surveying: pausing stops the network (fix before M4's human gate)

`PauseLayer.pauseGame` (PauseLayer.gd :31-47) sets `get_tree().paused = true`, and it is called on **window focus
loss** (:23-29, unless the `gameplay.streaming` setting is on), on a gamepad connect (:13-15), on the pause key
(:49-53), and when the **Steam overlay opens** (AchievementSteam.gd :115-117 emits `CurrentGame.pauseGame`). No mod
node sets `pause_mode`, so a paused tree stops CoopNet, Cell, RockSync and Npc: beacons, state, heartbeats and rock
streams all stop. One player alt-tabbing or opening the overlay to accept an invite drops out of everyone's view after
1.5 s (Cell treats a silent authority as gone). The dev loop hides this because background-launched windows never get
a focus-out event.

Fix (small, belongs to M4 or the start of M5):
1. `pause_mode = Node.PAUSE_MODE_PROCESS` on the mod's root node (modmain's DvCoop), so the network keeps running.
2. An extension of `PauseLayer.gd` that, **while in a cell** (Cell.inCell()), shows the menu without pausing:
   `$PauseContainer.visible = pause` and the mouse, but `tree.paused` stays false. Alone, the stock pause is
   untouched (done criterion 9). This one override covers focus loss, gamepad, overlay and the key.
   SPEC's "pause inside a cell pauses the cell" is dropped: one player's menu must not freeze three friends.

### Reconnect and "join at any time"

- Saves happen only on New Game, on pressing Dive (before the charge), on arrival back at Enceladus, and on the
  station's Save buttons (CurrentGame.gd :327-356). **Nothing saves during a dive**: quitting mid-dive (Menu,
  Exit, window close) puts the player back at Enceladus, pre-dive, with that dive's loot lost.
- A drop mid-dive therefore doesn't need a "rejoin the same dive": the dropped player's game keeps running and
  re-syncs from beacons when the transport comes back. If the game itself was closed, "rejoin" = Continue, then
  dive to the friend (the dive picker flow), which is the stock cost of a new dive.
- CoopNet keeps the lobby id; on a transport drop it retries `joinLobby` with backoff (1, 2, 4, 8 s, then every 15 s)
  and shows "reconnecting" in the friend panel.

## Proposed UI

All of it in Containers inside the stock containers above; text in the HUD font (NotoMono + outline); sizes in canvas
units so it follows the game's UI scale.

**Title screen, "Co-op" button** (in `Opts`, above Exit) opens a panel in `Popups`:

```
+-- Co-op --------------------------------------+
| [ Host a game ]   friends-only, up to 5       |
| [ Invite friends ]  (Steam overlay)           |
| Lobby: 3 players   [ Leave ]                  |
| --------------------------------------------- |
| Friends playing ΔV co-op:                     |
|   Alice   in lobby 1234...  [ Join ]          |
|   Bob     at Enceladus                        |
| Save slot for joining: [ A v ]                |
+-----------------------------------------------+
```

Joining from here loads the chosen slot with the stock Continue; the player arrives at Enceladus in the lobby.

**Pause menu, "Co-op" button** (after Resume): the same panel without "Save slot", plus a line per friend with
zone and range ("Alice, rings, 34 km").

**Astrogation panel (flight)**: friend rows appended to the destination list, `Alice (friend), 312 km`, plotted with
the stock Plot Course button; a friend marker (chevron + name) on the big ring map.

**Dive picker (Enceladus)**: friend rows `Alice (friend)` in the destination list; the stock price, depth and dv
panels apply; Dive lands the player a few km from the friend.

**Friend overlay (flight HUD, exists)**: adds "lobby: N, reconnecting..." to the off-ring list when the transport drops.

## Gate (dev automation where possible, plus two machines)

1. Title screen: Host, Invite and Join work with no launch options; the panel lays out cleanly at the six M3 gate-7
   resolutions and both UI-scale extremes (captures).
2. Steam invite accepted with the game **closed** (`+connect_lobby`) and **running** (`join_requested`): the invitee
   lands in the lobby at Enceladus on the chosen slot. Two Steam accounts.
3. Dive to friend: from Enceladus the joiner arrives within 5 km of the friend's position at the moment of arrival
   and forms a cell; the dive costs the stock price; the joiner's save changes only by the stock pre-dive save.
4. Plot course to friend: from more than 150 km away, the traveller arrives within 5 km of the friend's position at
   arrival time; nothing is added to `state.astrogation`; the friend's save is untouched (savecheck).
5. Pause in a cell: the pause key, alt-tab and the Steam overlay show the menu but nobody's simulation freezes; the
   cell keeps its authority (no handoff), the paused player's ship keeps streaming. Alone: stock pause.
6. Reconnect: pull the network for 20 s mid-cell; the player rejoins the same lobby and their own ship without a
   restart. Close the game mid-dive and rejoin via Continue + dive to friend.
7. Zero SCRIPT ERROR; savecheck passes on every machine for every flow above except the stock pre-dive save.
